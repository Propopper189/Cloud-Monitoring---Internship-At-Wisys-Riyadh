# Chapter 1: Introduction

## 1.1 Overview of Cloud Computing & Operations
Modern enterprise IT relies heavily on cloud computing models to deliver scalable, resilient, and high-performance applications. Organizations frequently adopt Multi-Cloud Architectures—combining services from platforms like Google Cloud Platform (GCP) and Huawei Cloud—to mitigate vendor lock-in, optimize geographical latency, and leverage best-of-breed specialized features. However, operating across distinct cloud ecosystems introduces significant management, monitoring, and security auditing overhead. 

## 1.2 Motivation for Automated Monitoring
In a multi-cloud environment, operations and security teams face diverse management consoles, distinct telemetry metrics, and incompatible logging schemas. If left unmonitored, infrastructure assets can undergo unauthorized configuration drift, critical VM/ECS instances can experience un-notified downtime, and security posture flags like disabled audit logs can remain undetected. Centralized infrastructure monitoring and event-driven alerting consolidate logs and audit trails, facilitating prompt response to threats and keeping operations aligned with corporate SLA parameters.

## 1.3 Context of Internship at AI Watania Information Systems (WiSys)
This academic project is directly modeled after practical technical challenges and operational workflows observed during an IT infrastructure internship at AI Watania Information Systems (WiSys) in Riyadh, Saudi Arabia. WiSys manages high-availability cloud infrastructure running critical database workloads, finance servers, and web applications. The internship focused on GCP Cloud Logging, Huawei CTS alarm configurations, subscription policies, and Entra ID application registration. 

This project implements a local prototype that translates those production monitoring scenarios into a controlled, cost-free, and safe simulation environment.
